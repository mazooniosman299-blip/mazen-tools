# Deployment and rollback
Production: existing free-plan Worker `mazentoolsfree`, configured in wrangler.jsonc. Do not delete or rename it. Pushes to main run the existing authorization, test, build, upload, exact-asset verification, public browser tests and rollback pipeline in .github/workflows/cloudflare.yml. No new paid service is configured.
Build: npm ci && npm run build. `dist/index.html` is at the archive root in the manual ZIP. Runtime libraries are bundled locally; no CDN dependency is required.
Staging is prepared, not deployed: build with SITE_ORIGIN set to the real staging HTTPS origin, then use `npx wrangler deploy --config wrangler.staging.jsonc` only with authorized Cloudflare access. This isolates the Worker name. No staging URL is claimed before deployment.
Manual production static deployment: upload the CONTENTS of dist/ or the deployment ZIP to Cloudflare Pages/Workers Static Assets. For Workers use the checked-in configuration; the static ZIP excludes development configuration and the optional crawler Worker. Rebuild SITE_ORIGIN if the hostname changes; canonical and sitemap must match. The Google file remains original, but the new URL property still needs Google validation.
Rollback: run the existing rollback.yml workflow with a recorded previous deployment version. deploy-workers.mjs snapshots the previous distribution and rolls back failed public verification when no newer release intervenes. Review Actions receipts, not only upload success.
The optional Sites registration is unpublished; production remains the existing Cloudflare Worker.
